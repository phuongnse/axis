# A requested change

Use this when the owner asks for a change in words, for example "give a
section more space".

1. Restate the request in Axis terms. Name each token, such as `primary` or
   `spacing-md`, and each widget, such as `table`, `form` or `section`. Ask the
   owner when the request is ambiguous.
2. Keep one look: before you change a part, check it on the whole page and the same control elsewhere, as [changing-a-part.md](changing-a-part.md#one-look-for-a-control) says.
3. Before you change a shared widget's behaviour, check each place that uses it, and take a change to another screen to the owner first, as [changing-a-part.md](changing-a-part.md#a-shared-widgets-users) says.
4. Open the artifact and make the change. Show the owner the result.
5. When the owner accepts it, write the NexKit issue as
   [Writing an issue](../axis-nexkit/SKILL.md#writing-an-issue) says. It links
   the artifact, names the tokens and widgets, links "Design tokens and
   previews" in the frontend reference, and has 2–5 criteria.
6. Add a change note to the artifact that names the issue by number and link.
   The note is the last one, so a later sync can find the issue.
