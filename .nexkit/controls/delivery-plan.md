# Axis delivery planning

Read the approved issue, AGENTS.md, docs/product-brief.md and the accepted
architecture before inspecting the actual source. Axis requirements are
self-contained; do not introduce unrelated project names, paths or references.

Produce a practical implementation plan within the approved scope. Identify
the affected code and contracts, data or workflow compatibility concerns,
access-control implications, and the unit, integration and end-to-end behaviors
needed to establish acceptance. Use the repository's actual commands and tests.
Treat previous reports and reviewer feedback as evidence to check, not approval
or permission to change the requirement.

Distinguish observed behavior, implementation proposals and open decisions.
Report missing product decisions or unavailable application/test prerequisites
as blocked. Do not choose a new architecture or widen scope to accommodate code.
This is a read-only task; return findings, file references, commands and
limitations without changing source or control files.
