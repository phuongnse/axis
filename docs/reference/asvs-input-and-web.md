# ASVS: input and the web

The requirements of ASVS chapters V1 to V5, on input, the web front end, APIs and files. How the rows are filled and checked is in [ASVS](asvs.md#how-it-is-filled).

## V5 File Handling

The requirements of ASVS chapter V5, on handling files.

| Id | Requirement | Status | Evidence |
| --- | --- | --- | --- |
| `V5.1.1` | Verify that the documentation defines the permitted file types, expected file extensions, and maximum size (including unpacked size) for each upload feature. Additionally, ensure that the documentation specifies how files are made safe for end-users to download and process, such as how the application behaves when a malicious file is detected. | **Met** | The permitted media types, extensions, maximum and unpacked size, and the handling of a malicious file are documented, see [file fields](file-fields.md#field-and-value). |
| `V5.2.1` | Verify that the application will only accept files of a size which it can process without causing a loss of performance or a denial of service attack. | **Met** | `Files:MaxSize` and the field's `maxSize` bound an upload, and the route answers `413` as soon as the count passes the limit. `FileUploadTests` covers it, see [file fields](file-fields.md#upload). |
| `V5.2.2` | Verify that when the application accepts a file, either on its own or within an archive such as a zip file, it checks if the file extension matches an expected file extension and validates that the contents correspond to the type represented by the extension.
