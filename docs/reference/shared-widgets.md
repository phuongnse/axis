# Shared widgets

This page says which shared widget does which job in the SPA, the working rule behind them and the
check that holds the code to it. The tokens are in [design tokens and previews](frontend.md#design-tokens-and-previews), and how
buttons, tables and fields look is in [actions and controls](actions-and-controls.md).

## The rule

One concern has one mechanism, because two ways to the same result drift apart and each fix reaches
only one of them. Before you add a prop, a context, a helper or a local variant, search for what
already does the job, in `web/src/platform/`, `web/src/designSystem/` and the server, and extend that
one.

- Never copy a component or its logic, fork it with a second way to the same result, or work round it
  in the caller.
- A caller that must build what its shared widget should know, such as the label of an option, shows
  that the widget or its data is incomplete. Fix it there, so every caller gets it.
- If a second mechanism already exists, merge the two in the same change.
- A new shared widget or helper gets its row in [which widget](#which-widget) in the same change.
- **A shared widget keeps no space around itself**. It draws no margin outside
  itself, and the screen that places it gives the space, so the widget sits in a card's gap as in a
  form's layout.
- **Ant Design through its documented API**. Axis uses Ant Design only through its documented props, tokens
  and semantic `classNames` and `styles`, never its `.ant-` class names, so an upgrade of Ant Design does not break a screen.
- **Every button is an `AxisButton`**. `AxisButton.tsx` is the one file that draws Ant Design's `Button`,
  so `axis/no-antd-button` holds with no disable comment.

## What the build checks

Oxlint in `npm run lint --prefix web`, which `scripts/lint.sh` runs, fails on each way round a shared
widget. The plugin rules are in `web/lint/axis-plugin.mjs` and are on in `web/.oxlintrc.json`. Test
files are not checked. The plugin's rule for the end-to-end tests is on in `tests/e2e/.oxlintrc.json`.

- **`axis/no-antd-button`** refuses a `<Button>` imported from `antd`. `AxisButton.tsx` is the one
  file that may use it.
- **`axis/no-antd-alert`** refuses an `<Alert>` imported from `antd`. `AxisAlert.tsx` is the one file
  that may use it.
- **`axis/no-card-panel`** refuses a `<Card>` imported from `antd` in a page under `src/pages/` or a `Console*`
  file in `src/platform/`, unless it has `size="small"`. A page's parts sit a rule apart, see
  [Parts a rule apart](shell.md#layout), so a page draws its panels through `SectionParts`. A small card is an item
  in a list, such as a Studio step. It accepts only the literal `small`, so a size from a variable, a spread or a
  condition is refused. It leaves `Card.Meta` and `Card.Grid` alone, and it does not see an import from a deep path
  such as `antd/es/card`, an import through `import * as`, or a full card drawn by a widget that a page renders.
- **`no-restricted-imports`** refuses a named `Table` import from `antd`. `AxisTable.tsx` is the one
  file that may use it. It does not see an import from a deep path such as `antd/es/table`.
- **`axis/field-label-through-axis-field`** refuses a hand-drawn field label: a `label` on Ant Design's
  `Form.Item`, a raw `<label>` or `<legend>`, or a text straight before an input. `AxisField` and
  `AxisFieldGroup` draw the labels. It is off in sign-in pages, the record form, a table's filter bar, `AxisField`,
  `AxisFieldGroup`, widget previews and tests. It matches syntax, so it does not see a label after its input, a text
  before a wrapper such as `Form.Item`, or a label drawn through a helper of the file's own.
- **`axis/no-antd-tag`** refuses a `<Tag>` imported from `antd`, also under another name. `StatusTag.tsx` is the one
  file that may use it. The table filter's removable chip is a control, not a tag, so it carries a disable comment
  with its reason, see [text](actions-and-controls.md#text).
- **`axis/no-antd-empty`** refuses an `<Empty>` imported from `antd`, also under another name. `EmptyState.tsx` is the
  one file that may use it, see [showing what is empty](actions-and-controls.md#showing-what-is-empty). It does not see
  an import from a deep path such as `antd/es/empty`, an import through `import * as`, or the empty text that an Ant
  Design widget draws itself.
- **An older use carries its reason.** Each `Button` that predates the rules has an
  `oxlint-disable-next-line <rule> -- <reason>` comment on the line before it. With
  `--report-unused-disable-directives`, a comment that its line no longer needs fails the lint, so the
  older uses only go down.

A unit test, `web/src/platform/sharedWidgets.test.ts`, holds [which widget](#which-widget) to the code.
Each name with a capital letter that a row without a planned marker names is exported by the SPA. Ant
Design's names and the rows that name a server path are left out. Each `Axis` widget that the SPA exports
is named in the table. The same test refuses a `<ul>` that is neither styled by `useBulletList` nor a plain list
with `listStyle: 'none'`. It reads the source text, so it does not see a list built with `createElement`.
The same test refuses a `.ant-` selector in any SPA source file outside the test files and `web/src/test/`, with no
allow-list. Test files may still find elements by Ant Design's classes, because they read its markup and do not style
it. It reads each line of source text, so it does not see a class name built from parts.
The same test refuses a resize cursor, such as `col-resize`, and a file with both `role="separator"` and `aria-valuenow`,
which is a size handle, in any SPA source file outside `ResizeHandle.tsx`. It reads source text, so it does not see a
handle built from parts, such as a cursor name joined at run time.
