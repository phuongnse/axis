# Package and module diagnostic codes

This page lists the codes that modules, packages, contracts and customization layers report, such as a reference to a module that is not declared. The shape of a diagnostic and the numbering rule are in [diagnostic codes](diagnostic-codes.md).

| Code | Meaning |
| --- | --- |
| `AXC0132` | An extension package manifest, `axis-package.json`, is missing, cannot be read, is not valid JSON or does not match its schema. Reported at startup by the host, at the failing JSON Pointer. Compilation reports it for an application's package at `packages/<id>/axis-package.json`, where a package folder without a manifest, or a file directly in `packages/`, gets it too. A file other than the manifest in a customer-hosted package's folder gets it at that file. An installed package whose manifest says `"runner": "customer"` gets it at `/runner`. |
| `AXC0133` | An extension package's folder names differ from its manifest's `id` or `version`. Reported at startup by the host, at `/id` or `/version`. Compilation reports it for an application's package at `packages/<id>/axis-package.json`, at `/id`. |
| `AXC0134` | An extension package's `assembly` file is missing or cannot be loaded, or the `adapter` file of a `node` or `python` package is missing. Reported at startup by the host, at `/assembly` or `/adapter`. |
| `AXC0135` | An extension package assembly's informational version, without build metadata after a `+`, differs from the manifest's `version`. Reported at startup by the host, at `/version`. |
| `AXC0136` | An extension package operation's `type` is not a class in the package assembly that implements `IOperation`, is not abstract and has a public parameterless constructor. Reported at startup by the host, at `/operations/{i}/type`. |
| `AXC0137` | An extension package operation name, or a field name in one operation's `input` or `output`, is already used, ignoring letter case. Reported at startup by the host, at the `name` of the later one. Compilation reports it for an application's package at `packages/<id>/axis-package.json`. |
| `AXC0138` | An extension package operation's `timeout` is not a positive ISO 8601 duration of at most `PT2M`. Reported at startup by the host, at `/operations/{i}/timeout`. Compilation reports it for an application's package at `packages/<id>/axis-package.json`. |
| `AXC0139` | An application's `packages` entry names a package id with no installed version. Reported in `application.json` at `/packages/{i}/id`. A module's `packages` entry gets the same code in `modules/<id>/module.json`. |
| `AXC0140` | An application's `packages` entry has a `version` range that is not an exact version `X.Y.Z`, `^X.Y.Z` or `~X.Y.Z`, with no leading zeros. Reported in `application.json` at `/packages/{i}/version`, or in `modules/<id>/module.json` for a module's entry. |
| `AXC0141` | No installed version of a package is in its `packages` entry's `version` range. Reported in `application.json` at `/packages/{i}/version`, listing the installed versions. Not checked when the package is unknown or the range is invalid. Reported in `modules/<id>/module.json` too, for a module's entry. A module's entry also gets it when the application pins the package outside the entry's range, and when no installed version meets the ranges of all the modules that list a package the application does not. |
| `AXC0142` | A package id appears in more than one `packages` entry. Reported in `application.json` at `/packages/{i}/id` of each later entry, which is not checked further. A module's `packages` get the same check in `modules/<id>/module.json`. |
| `AXC0146` | A release that is active, or has a running or waiting process instance, pins an extension package version that is not installed. Reported at the start of the server and the worker, in that release's stored `application.json` at `/packages/{i}/version`. It names the tenant, application, release, package id and version, and stops the start. [Activating a stored release](authoring.md#activating-a-release) that pins a version that is not installed gets the same code and is refused. |
| `AXC0147` | An application's package at `packages/<id>/` has the id of a package installed for the installation. Reported at `packages/<id>/axis-package.json`, at `/id`. |
| `AXC0148` | An application holds a package under `packages/<id>/` while `Extensions:ApplicationPackages` is off. Reported once for each package at `packages/<id>/axis-package.json`. A stored release still rebuilds with the setting off. It is never reported for a customer-hosted package. The MCP server's draft tools do not report it when the tenant's application packages switch is on, because the publisher checks the setting when it tests the package. A `test` request that names a package fails with it, too, and sends nothing to the host. |
| `AXC0149` | `application-package-host` refused the build of an application's package that a `publish` sent it, such as for a lock file that does not lock every dependency by hash, a failed install or a finding of the scan. Reported for each problem at `packages/<id>/<file>`, such as `packages/<id>/requirements.txt`. The `publish` fails at `compile` and stores no release. A `test` request that names the package fails with it, too, and stores no test. |
| `AXC0150` | A process package operation step's `operation` names a package that the application neither lists in `packages` nor holds under `packages/<id>/`, matched exactly. Not reported for a listed package that failed pinning (`AXC0139` to `AXC0142`), for a package folder that has its own problem, or when `application.json` was not loaded. Reported at `/steps/{i}/operation`. In a module process, the package must be one of the module's `packages` in `module.json`, and a package that only a module lists gives it in an application process. |
| `AXC0151` | A process package operation step's `operation` names no operation in the manifest of the pinned version, or of the application's own package, matched ignoring letter case. Reported at `/steps/{i}/operation`. Its `input` and `output` are then not checked. |
| `AXC0152` | `application-package-host` gave no answer to the build of an application's package that a `publish` sent it: it refused or closed the connection, or did not answer within 5 minutes. Reported once for each such package at `packages/<id>/axis-package.json`. The `publish` fails at `compile` and stores no release. A `test` request that names the package fails with it, too, and stores no test. The operator fixes it, see [an application's packages](extension-packages.md#an-applications-packages). |
| `AXC0200` | `module.json` is missing, unreadable, not JSON or fails its schema, or another file of the module version cannot be read. Reported at host start, at the failing pointer. A connector slot name, a slot operation name or a slot field name that repeats an earlier one in its list, ignoring letter case, is reported at its `name`. A copy of a module in a stored release without a valid `modules/<id>/module.json` is reported the same way, when the release is rebuilt. |
| `AXC0201` | The folder names differ from the manifest `id` or `version`. Reported at host start, at `/id` or `/version`. In a stored release, the folder `modules/<id>/` differing from the manifest `id` is reported the same way. |
| `AXC0202` | A module file has a kind that a module may not hold, or no kind. Reported at compile, at `/kind` of `modules/<id>/<relative path>`. |
| `AXC0203` | A `modules` entry names a module with no installed version. Reported in `application.json` at `/modules/{i}/id`, or in `modules/<id>/module.json` for an entry of a module's own `modules`. |
| `AXC0204` | A `modules` entry has a version range in no valid form. Reported at `/modules/{i}/version`, in `application.json` or in `modules/<id>/module.json`. |
| `AXC0205` | No installed version meets the one range that asks for the module. The message lists the installed versions. Reported at `/modules/{i}/version`, in `application.json` or in `modules/<id>/module.json`. Several ranges that no version meets together are `AXC0295`. |
| `AXC0206` | A module id appears twice in `modules`. Reported at `/modules/{i}/id` of each later entry, in `application.json` or in `modules/<id>/module.json`. |
| `AXC0207` | A field's `target` or `sequence`, a data source's or form's `entity`, a widget's or policy grant's `dataSource`, a site navigation entry's `page`, a trigger's, `startProcess` action's, process inspector's or sub-process step's `process`, an endpoint's `entity` or `process`, or a qualified rule call `<module id>:<name>(…)` names a module that `modules` does not declare. Reported at `/fields/{i}/target`, `/fields/{i}/sequence`, `/entity`, `/widgets/{i}/dataSource`, `/grants/{i}/dataSource`, `/navigation/{i}/page`, `/process`, `{actionPath}/process`, `/widgets/{i}/process`, `/steps/{i}/process` or the expression's pointer. A module that only another module depends on is not declared by the application, so a reference to it is reported too. A reference under a declared module that could not be pinned is not reported again. |
| `AXC0208` | A field's `target` or `sequence` in a module entity, the `entity` of a module event, data source, form or process, the `target` of a module data source parameter, a module process step's `form`, `event`, `process` or `entity`, a module trigger's `process`, `event` or `entity`, a module page's widget `entity`, `dataSource`, `form` or `process`, an action's `page` or `process` or a page parameter's `target`, or a module scenario step's `entity` or `process`, contains `/` and does not name a module that module declares. A `sequence`, a step `form`, a step `process`, a trigger `process`, a scenario step's `process` and every reference of a module page with `/` always give it, because a page names only its own module's resources. A scenario step's `entity` may name a declared module. Reported at that property in `modules/<id>/…`. |
| `AXC0209` | A module text key lacks the `<id>.` prefix. Reported at `/texts/{key}` of the module text, and at `/roles/{i}/label/textKey` of `modules/<id>/module.json` for a role slot label, and at `/connectors/{i}/label/textKey` for a connector slot label. A contract transition's message key is reported at `/lifecycle/transitions/{i}/message/textKey` of the contract file, and a contract core validation's at `/validations/{i}/message/textKey`. A contract point's label key is reported at `/…/label/textKey` of the contract file, for a point of the module, such as `/effects/{i}/label/textKey`. |
| `AXC0210` | An application locale has no text from a pinned module. The message names the locale. Reported in `application.json` at `/modules/{i}` for a declared module, and at `/modules` for a module that only another module depends on. |
| `AXC0211` | An application text key starts with the `<id>.` prefix of a module the application uses, declared or only depended on. Reported at `/texts/{key}`. |
| `AXC0212` | An application file sits under `modules/`, which releases reserve. Reported at that file, with an empty path. |
| `AXC0213` | The pinned version drops a module entity, drops one of its fields or changes a field's `type`, compared with the active release. The message names the module and both versions, and `none` when the module is removed. Reported at activation, at `/fields/{i}/type` of the module entity file in the release for a type change and at `/fields` for a dropped field. A dropped entity, or a removed module, is reported at the entity file of the active release, with an empty path. |
| `AXC0214` | A `migration` names a module entity wrongly. Its `entity` contains `/` and names a module that `application.json` does not declare, reported at `/entity`. Or a `dropEntity` change names a module entity, reported at `/changes/{i}/type`. Reported at compile. |
| `AXC0292` | A role slot of the pinned module version has no key in the entry's `roles`. The message names the slot, the module and the version. Reported in `application.json` at `/modules/{i}/roles`, or at `/modules/{i}` when the entry has no `roles`. An entry of a `module.json` is checked the same way for the role slots of the module it names, and reported in `modules/<id>/module.json` of the module that holds it. |
| `AXC0293` | A role slot is mapped to a name that is not a role the application declares. Reported at `/modules/{i}/roles/{slot}`, with `~` written `~0` and `/` written `~1`. A role whose file failed its own schema is not reported again. In an entry of a `module.json` the name must be a role slot of the module that holds the entry, matched exactly, and the report is in that `module.json`. |
| `AXC0294` | A key in the entry's `roles` is not a role slot of the pinned module version. The message lists the slots, or says there are none. Reported at `/modules/{i}/roles/{key}`, escaped the same way. It is reported the same way in `modules/<id>/module.json` for an entry of a module. |
| `AXC0295` | No installed version of a module meets every range that asks for it, and two or more ranges ask. The message names the application or each module that asks, with its range, and lists the installed versions. Reported at `/modules/{i}/version` of the application's own entry when the application asks, and otherwise of the first asking module's `modules/<id>/module.json`. See [resolving the graph](modules-and-templates.md#processes-pages-policies-and-dependencies). |
| `AXC0296` | Modules depend on each other in a cycle, and a module that depends on itself is a cycle. The message names the cycle. Reported once for each cycle, at `/modules/{i}/id` of the entry that closes it, in `modules/<id>/module.json`. |
| `AXC0297` | A connector slot of the pinned module version has no key in the entry's `connectors`. The message names the slot, the module and the version. Reported in `application.json` at `/modules/{i}/connectors`, or at `/modules/{i}` when the entry has no `connectors`. An entry of a `module.json` is checked the same way for the connector slots of the module it names, and reported in `modules/<id>/module.json` of the module that holds it. |
| `AXC0298` | A connector slot is mapped to a name that is not a connector the application declares, ignoring letter case. Reported at `/modules/{i}/connectors/{slot}`, with `~` written `~0` and `/` written `~1`. A connector whose file failed its own schema is not reported again. In an entry of a `module.json` the name must be a connector slot of the module that holds the entry, matched exactly, and the report is in that `module.json`. |
| `AXC0299` | A key in the entry's `connectors` is not a connector slot of the pinned module version. The message lists the slots, or says there are none. Reported at `/modules/{i}/connectors/{key}`, escaped the same way. It is reported the same way in `modules/<id>/module.json` for an entry of a module. |
| `AXC0300` | The connector a slot is mapped to has no operation with the name of an operation of the slot, ignoring letter case. The message names the slot, the connector and the operation. Reported at `/modules/{i}/connectors/{slot}`. In an entry of a `module.json` the slot of the depending module takes the place of the connector, and the report is in that `module.json`. |
| `AXC0301` | An input of a slot operation is not an input of the connector's operation with the same type. The message names the slot, the operation and the field, and both types when the field exists. Reported at `/modules/{i}/connectors/{slot}`. In an entry of a `module.json` the slot of the depending module takes the place of the connector, and the report is in that `module.json`. |
| `AXC0302` | An input of the connector's operation is required, and the slot operation has no input with that name. The message names the slot, the operation and the field. Reported at `/modules/{i}/connectors/{slot}`. In an entry of a `module.json` it is checked against the connector that the chain of slots reaches, and the report is in that `module.json`. |
| `AXC0303` | An output of a slot operation is not an output of the connector's operation with the same type. The message names the slot, the operation and the field, and both types when the field exists. Reported at `/modules/{i}/connectors/{slot}`. In an entry of a `module.json` the slot of the depending module takes the place of the connector, and the report is in that `module.json`. |
| `AXC0304` | A role in a module policy's `roles` is not a role slot of its module. The message lists the slots, or says there are none. Reported at `/roles/{i}` of the module file. |
| `AXC0305` | A grant in a module policy is on something other than an entity, data source or process of its own module: an `endpoint` grant, a name with `/` such as `organization/Department`, or the plain name of an application entity, data source or process. Reported at `/grants/{i}/entity`, `/grants/{i}/dataSource`, `/grants/{i}/process` or `/grants/{i}/endpoint` of the module file. |
| `AXC0306` | Two mappings of the same slot of a module give it different roles or different connectors: the application's own entry and the chain through a depending module, or the chains through two depending modules. The message names the slot, the module and both mappings. The application's entry stays, and otherwise the first depending module in pin order. Reported at `/modules/{i}/roles/{slot}` or `/modules/{i}/connectors/{slot}` of the later entry, in `modules/<id>/module.json`. See [mapping slots](modules-and-templates.md#processes-pages-policies-and-dependencies). |
| `AXC0307` | A module task's `assignee.role`, or an escalation's `reassign.role`, is not a role slot of its module. A role of an application gives this too. The message lists the slots, or says there are none. Reported at `/steps/{i}/assignee/role` or `/steps/{i}/escalations/{j}/reassign/role` of the module file. |
| `AXC0320` | A `contract` file is in an application folder. Only a module holds contracts. Reported at `/kind`, and the file is not loaded. See [the contract resource](module-contracts.md#the-contract-resource). |
| `AXC0321` | The `entity` of a module contract names no entity of the same module, or is not a plain name because it contains `/`. A module entity file that failed its own schema is not reported again. Reported at `/entity` of the contract file in `modules/<id>/`. See [the contract resource](module-contracts.md#the-contract-resource). |
| `AXC0322` | The `entity` of a module contract is a child entity. The message names its owner. Reported at `/entity`. See [the contract resource](module-contracts.md#the-contract-resource). |
| `AXC0323` | A module has a second contract for the same entity, ignoring letter case. Reported at `/entity` of the later file, naming the first. See [the contract resource](module-contracts.md#the-contract-resource). |
| `AXC0324` | A module contract has none of `lifecycle`, `validations`, `effects` and `ceiling`. Reported at the root of the file, with an empty path. See [the contract resource](module-contracts.md#the-contract-resource). |
| `AXC0325` | The `field` of a contract's lifecycle names no field of the entity, or a field that is not an `enum`, is not `required`, is computed or is `sensitive`. The message says which. Reported at `/lifecycle/field`. See [lifecycle](module-contracts.md#lifecycle). |
| `AXC0326` | The states of a contract's lifecycle do not match the values of its state field. A state that is not exactly one of the values is reported at `/lifecycle/states/{i}/name`. A value with no state is reported at `/lifecycle/states`, once for each value. Not checked when the state field is `AXC0325`. See [lifecycle](module-contracts.md#lifecycle). |
| `AXC0327` | No state of a contract's lifecycle is `initial`. Reported at `/lifecycle/states`. See [lifecycle](module-contracts.md#lifecycle). |
| `AXC0328` | A state, a transition, a core validation or an effect of a contract has a name that an earlier one in its list already has, ignoring letter case. Reported at `/lifecycle/states/{i}/name`, `/lifecycle/transitions/{i}/name`, `/validations/{i}/name` or `/effects/{i}/name` of the later one. See [lifecycle](module-contracts.md#lifecycle), [core validations](module-contracts.md#core-validations) and [effects of a transition](module-contracts.md#effects-of-a-transition). |
| `AXC0329` | A `from` or `to` of a contract's transition names no state of the lifecycle. Reported at `/lifecycle/transitions/{i}/from/{j}` or `/lifecycle/transitions/{i}/to`. See [lifecycle](module-contracts.md#lifecycle). |
| `AXC0330` | A pair of a `from` state and the `to` state already belongs to an earlier transition. Reported at `/lifecycle/transitions/{i}/from/{j}`, naming that transition. See [lifecycle](module-contracts.md#lifecycle). |
| `AXC0331` | The `to` state of a contract's transition is also in its `from`. Reported at `/lifecycle/transitions/{i}/to`. See [lifecycle](module-contracts.md#lifecycle). |
| `AXC0332` | A key of a contract's `ceiling.slots` is not a role slot of the module. Reported at `/ceiling/slots/{slot}`, listing the slots. See [grant ceiling](module-contracts.md#grant-ceiling). |
| `AXC0333` | A field of a ceiling entry is not a field of the contract's entity. Reported at `/ceiling/slots/{slot}/{i}/fields/{j}` or `/ceiling/others/{i}/fields/{j}`. See [grant ceiling](module-contracts.md#grant-ceiling). |
| `AXC0334` | A grant on a module entity goes past the ceiling of a role: no entry of the role lists one of its actions, or its fields are outside the fields of the entries that list the action. Reported once for each role at `/grants/{i}` of the application or module policy, naming the role, the actions and the fields past. See [grant ceiling](module-contracts.md#grant-ceiling). |
| `AXC0335` | A role in a module scenario's `users`, an `assignee.role` of an `expectTask` step or a `recipient.role` of an `expectNotification` step is not a role slot of its module. A role of an application gives this too. Roles are matched exactly. The message lists the slots, or says there are none. Reported at `/users/{user}/{j}`, `/steps/{i}/assignee/role` or `/steps/{i}/recipient/role` of the module file. See [module scenarios](modules-and-templates.md#processes-pages-policies-and-dependencies). |
| `AXC0338` | A seed record of an entity whose module contract has a lifecycle gives a state, as text, that is not an initial state. The message lists the initial states. A record that leaves the state out or gives a value that is not text is left to the startup step. Reported at `/records/{i}/values/<state field>` of the seed file. See [where the contract is checked](module-contracts.md#where-the-contract-is-checked). |
| `AXC0339` | A point in a module scenario's `contract.covers` is not a named point of a contract of that module. Points are matched exactly, with the letter case the contract writes. The message says when the module has no contracts. Reported at `/contract/covers/{i}` of the module file. See [contract scenarios](module-contracts.md#contract-scenarios) and [named points](module-contracts.md#named-points). |
| `AXC0340` | An application's own scenario has `contract`. Only a module's scenario can be a contract scenario. Reported at `/contract`. See [contract scenarios](module-contracts.md#contract-scenarios). |
| `AXC0342` | A contract scenario of a pinned module failed in the `contracts` step of a `publish` or `validate` request. The message names the module, the scenario and the failure. Reported once for each failing scenario, at `/steps/{i}` of the module's scenario file, with the index of the failing step. Nothing is stored or activated. See [contract scenarios](module-contracts.md#contract-scenarios) and [publishing](authoring.md#publishing). |
| `AXC0344` | The `on` of a contract's effect names no transition of the same contract, with the same letter case. The message lists the transitions, or says the contract has no lifecycle. Reported at `/effects/{i}/on`. See [effects of a transition](module-contracts.md#effects-of-a-transition). |
| `AXC0345` | The `create.entity` of a contract's effect is not a plain name because it contains `/`, names no entity of the same module, or names a child entity, whose message names its owner. A module entity file that failed its own schema is not reported again. Reported at `/effects/{i}/create/entity`. See [effects of a transition](module-contracts.md#effects-of-a-transition). |
| `AXC0346` | A key of an effect's `create.values` names no field of the created entity, names a field an earlier key of the effect already sets, ignoring letter case, or names a field an effect cannot set: a computed, sequence, child collection, `references`, matched or creator field. Reported at `/effects/{i}/create/values/{field}`. An expression that does not fit the field reports its expression code at the same path. See [effects of a transition](module-contracts.md#effects-of-a-transition). |
| `AXC0347` | The `target` of a layer names nothing in a module that `application.json` lists. The module is not listed, or the module has no resource of that name. A module the application reaches only through another module counts as not listed. A module that is listed but could not be pinned gets no code here, its own entry already has one. Reported at `/target`. See [the layer resource](customization-layers.md#the-layer-resource). |
| `AXC0348` | The `target` of a layer is a `scenario` of the module, or is `<module id>/module`, which names the module's `module.json`, when the module has no resource named `module`. Reported at `/target`. See [the layer resource](customization-layers.md#the-layer-resource). |
| `AXC0349` | A layer is not the file `customizations/<target>.json`, with the `target` written exactly. The message gives the expected path. Reported at `/target`. See [the layer resource](customization-layers.md#the-layer-resource). |
| `AXC0350` | A layer has the target of an earlier layer in path order, ignoring letter case. The message names the first file. Reported at `/target` of the later file. See [the layer resource](customization-layers.md#the-layer-resource). |
| `AXC0351` | The `changes` of a layer set `id`, `kind`, `name` or `formatVersion`. Reported at `/changes/<property>` for each one set. See [the layer resource](customization-layers.md#the-layer-resource). |
| `AXC0352` | The `target` of a layer names a resource whose name more than one kind of resource has in the module, ignoring letter case, such as a data source and a page. The message lists the kinds. A target has no way to say which one is meant, so such a resource cannot be targeted yet. Reported at `/target`. See [the layer resource](customization-layers.md#the-layer-resource). |
| `AXC0356` | A `relax` entry of an application's module entry names a point that is not a named point of the pinned version's contracts. Points are matched exactly, with the letter case the contract writes. A point that a newer pinned version no longer has is the same code, so an entry never silently stops meaning anything. The message says when the version has no contracts. Reported at `/modules/{i}/relax/{j}` of `application.json`. See [relax entries](module-contracts.md#relax-entries) and [named points](module-contracts.md#named-points). |
| `AXC0357` | A `relax` entry names a point that an earlier entry of the same module entry already names. Only the second and later entries are reported, and only for a known point. Reported at `/modules/{i}/relax/{j}` of `application.json`. See [relax entries](module-contracts.md#relax-entries) and [named points](module-contracts.md#named-points). |
| `AXC0358` | A `relax` entry has no `reason`, or a `reason` that is empty or only white space. A reason of more than 500 characters is a schema violation instead. Reported at `/modules/{i}/relax/{j}` of `application.json`. See [relax entries](module-contracts.md#relax-entries) and [named points](module-contracts.md#named-points). |
| `AXC0364` | A layer removes an element with `"remove": true` whose key the module's list lacks, ignoring letter case. An element that is not a remove with an unknown key is an added element, not a problem. Reported at `/changes/.../{i}/<key>` of the layer file, such as `/changes/steps/2/name`. The layer is not applied. See [applying a layer](customization-layers.md#applying-a-layer) and [list keys](customization-layers.md#list-keys). |
| `AXC0365` | A layer element with `"remove": true` holds a property besides its key and `remove`, or a layer's `changes` has `"remove": true` beside another property.
