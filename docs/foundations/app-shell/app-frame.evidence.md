## Current verification

- The current Reference Product deployment owns the recorded Compose topology. Its documented trusted Axis-E2E wrapper ran the canonical Axis browser service and passed all 5 App Frame browser tests without snapshot updates.
- Held-response Account journeys prove that Workspace and preference actions expose semantic busy state in the same click turn, retain stable geometry through completion, and return to rest before visual comparison.
- Account accepts typed Workspace and preference state instead of feature-rendered subsystem slots. Browser evidence compares all four semantic regions for one symmetric inset and verifies the Create Organization resting boundary before visual capture.
- The Workspace adapter projects the personal context through the canonical `Personal` relationship label while preserving server-projected Organization names; the focused accessible-name contract proves that the signed-in identity is not repeated as the personal Workspace label.
- AT-002 includes a compact-height Account journey with 12 eligible organization Workspaces; keyboard focus reaches sign-out, the focused action remains in view, and the document does not become a scroll owner.
- The accepted matrix contains the four canonical EN light/dark × desktop/compact Account captures plus one intentional VI 320 CSS-pixel capture under WCAG text-spacing stress. The canonical helper continues to reject accidental non-EN captures; the VI artifact is emitted only by the named reflow test. The identity avatar is top-aligned with the primary identity text in every accepted capture and has an explicit browser geometry assertion.
- Browser evidence enumerates every visible Account text node for >=4.5:1 contrast in light and dark, asserts 32 CSS-pixel desktop and 44 CSS-pixel compact target roles, proves long human/email labels wrap, checks the semantic accessibility tree, applies text-spacing overrides at the 320 CSS-pixel reflow boundary, keeps focused sign-out visible, and rejects page/surface overflow, document scrolling, console errors, and page errors. These checks found and drove fixes for a prior long-email intrinsic-width overflow and a prior light destructive-action contrast failure.
- [The scoped standards assessment](./account-surface.assessment.md) records every WCAG 2.2 A/AA criterion as Pass or N/A with evidence/rationale, maps interaction/human-centred principles, and inventories ownership/retirement. Accepted review is current for the complete Account surface, including the top-aligned identity icon. Account is enforced with no profile gaps. This remains a scoped surface assessment, not a product-wide WCAG or ISO certification claim.
- The typed active-surface registry has one Account consumer. Page actions, bounded confirmation actions, and inline prompt actions have different relationships and owners, so the standalone section-action presentation remains local to Account until another representative consumer proves the same semantic role.
