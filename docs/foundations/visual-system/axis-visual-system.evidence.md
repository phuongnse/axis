## Current verification

- `frontend/ui-foundation.json` is the strict lifecycle plus contract/evidence manifest. `check ui-foundation` rejects `verified` or `enforced` state without version-controlled perceptual evidence and rejects drift between state and the separate `enforcedContracts` registry. The finite consumer mapping lives in typed source, its enforced-contract union is derived from that registry, and the real-symbol registry is compiler-checked for missing or extra owners and implementations. Contract owners require a compatible surface id, while focused component/browser evidence asserts the emitted id/contract markers. No filename or source-text import pattern is treated as architectural proof. Reusable visual values are separately projected from the canonical theme into the typed `axisStyles` contract; an AST-based consumption gate only prevents authored code from bypassing that contract.
- Account is the first clean-cutover proving surface. Focused component evidence covers its semantic API, identity, Workspace continuity and recovery, preferences, sign-out, keyboard behavior, stable pending geometry, immediate user-action feedback, delayed passive-content feedback, and a long compact eligible-Workspace set. The held-response browser journey asserts immediate semantic busy state and persistent target emphasis without premature current semantics. The canonical EN light/dark × desktop/compact baseline set is present, was inspected for stable anatomy and geometry, passed the current five-test App Frame browser run without snapshot updates through the topology-owning Reference Product wrapper, and received explicit project-owner visual acceptance on 2026-08-11. VI behavior, selection, busy state, responsive layout, and overflow remain covered by browser assertions without duplicating the golden image source of truth. That acceptance is scoped to Account; the remaining contracts retain their named perceptual-evidence gap.
- Authenticated Frame, Resource Workspace, and Managed Task Window retain their existing focused component and browser journeys. Entry Surface and Process Workbench now have one shared owner each and registered direct consumers. All five remain explicitly `defined`; equivalent committed perceptual baselines are still required before any can advance to `verified` or `enforced` and before the visual-system Tests status can become `Done`.
