## Current verification

- `frontend/ui-coverage-profile.json` defines `axis-ui-v1`: an auditable visual, behavioral, external-standard, and lifecycle requirement set with required evidence kinds, representative modes, and invalidation triggers. The requirement count is version-specific rather than a universal sufficiency claim. `frontend/ui-foundation.json` must classify every requirement exactly once as covered, gap, or explicitly allowed not-applicable. `check ui-foundation` resolves covered entries to real Acceptance Test Matrix ids and matching evidence-sidecar rows, requires the referenced evidence to be declared by the contract and satisfy the profile's evidence kinds and modes, distinguishes missing/candidate/accepted perceptual artifacts, rejects advanced state with gaps or pending acceptance, and rejects drift between state and `enforcedContracts`. The checker enforces traceability, not WCAG/ISO conformance or perceptual adequacy; those still require criterion-level assessment and review.
- The finite consumer mapping lives in typed source, its enforced-contract key set is derived from the manifest registry, and the real-symbol registry is compiler-checked for missing or extra owners and implementations. Contract owners require a compatible surface id, while focused component/browser evidence asserts emitted id/contract markers. No filename or source-text import pattern is treated as architectural proof. Reusable visual values are separately projected from the canonical theme into the typed `axisStyles` contract; an AST-based consumption gate only prevents authored code from bypassing that contract. Project-owner authority and review authenticity remain task or pull-request evidence, not manifest claims.
- Account is the first `axis-ui-v1` enforced clean-cutover surface. Focused component/browser evidence covers its semantic API, complete owner anatomy, top-aligned identity icon, Workspace continuity/recovery, preferences, sign-out, keyboard behavior, pending geometry, target density, all-visible-text contrast, long content, VI localization, text spacing, 320 CSS-pixel reflow, and constrained-height scroll ownership. Its accepted matrix contains four canonical EN light/dark × desktop/compact captures plus one VI compact reflow capture. The scoped criterion-level standards/retirement assessment, typed consumer registry, accepted review, and all eighteen requirement traces are current.
- Authenticated Frame is the second enforced clean-cutover `axis-ui-v1` surface. Its complete owner/consumer inventory, criterion-level assessment, component/browser evidence, five accepted captures, current review, and all eighteen requirement traces are current.
- Entry Surface is accepted and enforced. Its single owner, six real consumers, criterion-level technical assessment, focused component and journey evidence, clean-cutover sweep, responsive density and first-line consent-alignment guards, five inspected accepted captures, and project-owner review cover all eighteen current profile requirements.
- Resource Workspace is accepted and enforced. Its shared owner and DataTable map five real consumers; component/browser evidence covers collection states, finite ownership, internal overflow, 32/44 CSS-pixel control density, keyboard/pointer behavior, reduced motion, EN/VI localization, 320 CSS-pixel text-spacing reflow, and five inspected accepted captures. Its criterion-level assessment, clean-cutover proof, current review, and all eighteen requirement traces are complete.
- Managed Task Window is a technically complete candidate. Its typed theme layer utilities materialize the canonical `modal` and `managed` z-order, while browser hit testing proves the compact dock tray remains topmost over a fullscreen window. The single `Windows (N)` switcher sits at the leading edge of the active footer and falls back to the tray only when all windows are minimized. Shared action adapters preserve 44/32 CSS-pixel control geometry; header chrome aligns top-right with the title on desktop and centers between full-width identity and description rows on compact viewports. Five candidate captures cover light/dark desktop/compact plus VI at 320 CSS pixels. Fifteen non-review profile requirements are covered; the three standards requirements remain gaps until project-owner review. Process Workbench retains all-profile gaps. Existing journeys or artifacts do not advance lifecycle by themselves; requirement-complete evidence and project-owner acceptance are both required before those contracts can advance.
